SOAL 1: EXERCISE 3.21 - U.S. HOUSE OF REPRESENTATIVES VOTING (Bobot 25%)
================================================================================
A. Ringkasan Kebutuhan:
   Mencatat sesi voting selama periode kongres 2 tahunan:
   - STATE: Nama negara bagian (unik), Region (Northeast, Midwest, Southeast, Southwest, West).
   - CONGRESS_PERSON: Nama, Distrik yang diwakili, Start_Date saat pertama terpilih,
     Partai politik (Republican, Democrat, Independent, Other).
   - BILL: Nama RUU (unik), Tanggal voting, Status kelulusan (Yes, No), Sponsor (anggota kongres).
   - VOTE: Suara tiap anggota pada tiap RUU (domain: Yes, No, Abstain, Absent).

B. Rancangan Entitas & Relasi (Logical Model):
   1. Entitas STATE
      - State_Name : VARCHAR(50) [Primary Key]
      - Region     : VARCHAR(20) [CHECK: Region IN ('Northeast', 'Midwest', 'Southeast', 'Southwest', 'West')]

   2. Entitas CONGRESS_PERSON
      - Congress_Person_Id : INT atau SERIAL [Primary Key]
      - Name               : VARCHAR(100) [Mandatory]
      - State_Name         : VARCHAR(50) [FK -> STATE.State_Name]
      - District           : INT [Mandatory]
      - Start_Date         : DATE [Mandatory]
      - Party              : VARCHAR(20) [CHECK: Party IN ('Republican', 'Democrat', 'Independent', 'Other')]

   3. Entitas BILL
      - Bill_Id          : INT atau SERIAL [Primary Key]
      - Bill_Name        : VARCHAR(150) [Unique, Mandatory]
      - Date_Of_Vote     : DATE [Mandatory]
      - Passed_Or_Failed : VARCHAR(5) [CHECK: Passed_Or_Failed IN ('Yes', 'No')]

   4. Entitas BILL_SPONSOR (Relasi M:N antara CONGRESS_PERSON dan BILL)
      - Bill_Id            : INT [FK -> BILL.Bill_Id, PK]
      - Congress_Person_Id : INT [FK -> CONGRESS_PERSON.Congress_Person_Id, PK]

   5. Entitas VOTE (Relasi M:N dengan atribut Vote)
      - Congress_Person_Id : INT [FK -> CONGRESS_PERSON.Congress_Person_Id, PK]
      - Bill_Id            : INT [FK -> BILL.Bill_Id, PK]
      - Vote_Cast          : VARCHAR(10) [CHECK: Vote_Cast IN ('Yes', 'No', 'Abstain', 'Absent')]

SOAL 2: EXERCISE 3.34 - CONFERENCE REVIEW DATABASE (Bobot 35%)
================================================================================
A. Ringkasan Kebutuhan:
   Sistem peninjauan makalah ilmiah (paper review):
   - Author diidentifikasi unik dengan Email_Id, nama depan, nama belakang.
   - Paper memiliki Paper_Id unik, judul, abstrak, nama file elektronik.
   - Paper dapat memiliki banyak author, salah satunya sebagai Contact Author.
   - Reviewer diidentifikasi unik dengan Email_Address, nama depan, belakang, no telp, afiliasi, topik minat.
   - Setiap paper ditugaskan ke 2 hingga 4 reviewer.
   - Reviewer menilai paper pada 4 kategori nilai 1-10:
     Technical Merit, Readability, Originality, Relevance.
   - Overall Recommendation (Accept / Reject).
   - Dua jenis komentar tertulis: Committee Comments (khusus panitia) dan Author Feedback.

B. Rancangan Entitas & Relasi (Logical Model):
   1. Entitas AUTHOR
      - Author_Email : VARCHAR(100) [Primary Key]
      - First_Name   : VARCHAR(50) [Mandatory]
      - Last_Name    : VARCHAR(50) [Mandatory]

   2. Entitas PAPER
      - Paper_Id            : INT atau SERIAL [Primary Key]
      - Title               : VARCHAR(255) [Mandatory]
      - Abstract            : TEXT [Mandatory]
      - File_Name           : VARCHAR(255) [Mandatory]
      - Contact_Author_Email: VARCHAR(100) [FK -> AUTHOR.Author_Email, Mandatory]

   3. Entitas PAPER_AUTHOR (Relasi M:N Author - Paper)
      - Paper_Id     : INT [FK -> PAPER.Paper_Id, PK]
      - Author_Email : VARCHAR(100) [FK -> AUTHOR.Author_Email, PK]
      - Author_Order : INT [Urutan penulis: 1 = Penulis pertama, dll.]

   4. Entitas REVIEWER
      - Reviewer_Email : VARCHAR(100) [Primary Key]
      - First_Name     : VARCHAR(50) [Mandatory]
      - Last_Name      : VARCHAR(50) [Mandatory]
      - Phone_Number   : VARCHAR(30)
      - Affiliation    : VARCHAR(100)

   5. Entitas REVIEWER_TOPIC (Atribut Multivalued topik minat reviewer)
      - Reviewer_Email : VARCHAR(100) [FK -> REVIEWER.Reviewer_Email, PK]
      - Topic          : VARCHAR(100) [PK]

   6. Entitas REVIEW_ASSIGNMENT (Relasi M:N Reviewer - Paper dengan penilaian)
      - Paper_Id               : INT [FK -> PAPER.Paper_Id, PK]
      - Reviewer_Email         : VARCHAR(100) [FK -> REVIEWER.Reviewer_Email, PK]
      - Technical_Merit        : INT [CHECK: 1 s.d 10]
      - Readability            : INT [CHECK: 1 s.d 10]
      - Originality            : INT [CHECK: 1 s.d 10]
      - Relevance              : INT [CHECK: 1 s.d 10]
      - Overall_Recommendation : VARCHAR(20) [e.g., 'Strong Accept', 'Accept', 'Reject', 'Strong Reject']
      - Committee_Comments     : TEXT
      - Author_Feedback        : TEXT

SOAL 3: EXERCISE 3.35 - AIRLINE DATABASE (Figure 3.21) (Bobot 40%)
================================================================================
A. Ringkasan Kebutuhan (Berdasarkan Gambar 3.21 Elmasri):
   - AIRPORT: Airport_Code (PK), Name, City, State.
   - FLIGHT: Flight_Number (PK), Airline, Weekdays.
   - FLIGHT_LEG (Entitas Lemah dari FLIGHT):
     Leg_No, Scheduled_Dep_Time, Scheduled_Arr_Time.
     Relasi: Departure_Airport (1:N) dan Arrival_Airport (1:N).
   - FARE: Code (PK lokal), Amount, Restrictions. Relasi ke FLIGHT.
   - AIRPLANE_TYPE: Type_Name (PK), Max_Seats, Company.
   - CAN_LAND: Relasi M:N antara AIRPLANE_TYPE dan AIRPORT.
   - AIRPLANE: Airplane_Id (PK), Total_No_Of_Seats. Relasi ke AIRPLANE_TYPE.
   - LEG_INSTANCE: Terjadinya leg pada tanggal tertentu:
     Date, No_Of_Avail_Seats, Dep_Time, Arr_Time.
     Relasi: Ditugaskan ke AIRPLANE, serta bandara keberangkatan & kedatangan aktual.
   - SEAT / RESERVATION: Kursi pada LEG_INSTANCE yang dipesan:
     Seat_No, Customer_Name, Cphone.

B. Rancangan Entitas & Relasi (Logical Model):
   1. Entitas AIRPORT
      - Airport_Code : VARCHAR(10) [Primary Key]
      - Name         : VARCHAR(100)
      - City         : VARCHAR(50)
      - State        : VARCHAR(50)

   2. Entitas AIRPLANE_TYPE
      - Type_Name : VARCHAR(50) [Primary Key]
      - Max_Seats : INT
      - Company   : VARCHAR(50)

   3. Entitas CAN_LAND (Relasi M:N AIRPLANE_TYPE - AIRPORT)
      - Type_Name    : VARCHAR(50) [FK -> AIRPLANE_TYPE.Type_Name, PK]
      - Airport_Code : VARCHAR(10) [FK -> AIRPORT.Airport_Code, PK]

   4. Entitas AIRPLANE
      - Airplane_Id       : INT [Primary Key]
      - Total_No_Of_Seats : INT
      - Type_Name         : VARCHAR(50) [FK -> AIRPLANE_TYPE.Type_Name]

   5. Entitas FLIGHT
      - Flight_Number : VARCHAR(20) [Primary Key]
      - Airline       : VARCHAR(50)
      - Weekdays      : VARCHAR(50)

   6. Entitas FARE
      - Flight_Number : VARCHAR(20) [FK -> FLIGHT.Flight_Number, PK]
      - Fare_Code     : VARCHAR(20) [PK]
      - Amount        : NUMERIC(10,2)
      - Restrictions  : VARCHAR(255)

   7. Entitas FLIGHT_LEG
      - Flight_Number          : VARCHAR(20) [FK -> FLIGHT.Flight_Number, PK]
      - Leg_No                 : INT [PK]
      - Departure_Airport_Code : VARCHAR(10) [FK -> AIRPORT.Airport_Code]
      - Arrival_Airport_Code   : VARCHAR(10) [FK -> AIRPORT.Airport_Code]
      - Scheduled_Dep_Time     : TIME
      - Scheduled_Arr_Time     : TIME

   8. Entitas LEG_INSTANCE
      - Flight_Number          : VARCHAR(20) [PK]
      - Leg_No                 : INT [PK]
      - Flight_Date            : DATE [PK]
      - Airplane_Id            : INT [FK -> AIRPLANE.Airplane_Id]
      - Departure_Airport_Code : VARCHAR(10) [FK -> AIRPORT.Airport_Code]
      - Arrival_Airport_Code   : VARCHAR(10) [FK -> AIRPORT.Airport_Code]
      - Dep_Time               : TIME
      - Arr_Time               : TIME
      - No_Of_Avail_Seats      : INT

   9. Entitas SEAT_RESERVATION
      - Flight_Number : VARCHAR(20) [PK]
      - Leg_No        : INT [PK]
      - Flight_Date   : DATE [PK]
      - Seat_No       : VARCHAR(10) [PK]
      - Customer_Name : VARCHAR(100)
      - Customer_Phone: VARCHAR(30)
